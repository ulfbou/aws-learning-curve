# ADR-013: Separation of Learning Content and Learner State

- Status: Accepted
- Date: 2026-11-02

## Context

AWS Learning Curve contains repository objects, source material, generated release artifacts, and a schema for private study state.

These categories have different meanings and lifecycles.

Without an explicit separation, repository status can be mistaken for learner understanding, source registration can be mistaken for authority, and private learner observations can accidentally enter public release data.

## Decision

The architecture distinguishes:

```text
repository content state
learner state
source material
generated release artifacts
```

These categories must not be treated as interchangeable.

## Repository content state

Repository content state describes the lifecycle of a durable repository object.

The current statuses are:

```text
candidate
published
deprecated
rejected
```

Their meanings are:

- `candidate` — proposed repository content awaiting review;
- `published` — accepted repository content available for normal use;
- `deprecated` — retained but superseded or no longer recommended;
- `rejected` — reviewed but not accepted.

These statuses do not describe learner mastery.

A published object may still be misunderstood.

A candidate explanation may still be useful in a study interaction.

## Learner state

Learner state describes the learner's interaction with the material.

Examples include:

- question attempts;
- scenario responses;
- confidence;
- remaining uncertainty;
- difficulty judgments;
- misconception observations;
- review history;
- forgotten concepts;
- current priorities;
- delayed-recall results;
- transfer performance.

Learner state is private by default.

It must not enter:

```text
public/data/
```

It must not be added to public bundle generation.

It must not automatically mutate shared learning content.

## Source material

Source material is learning input.

Examples include:

- course notes;
- personal notes;
- classroom material;
- video transcriptions;
- AWS documentation;
- lab observations;
- experiments;
- mistakes and corrections.

Source records help the learner:

- revisit the original material;
- remember where an idea arose;
- distinguish source material from later synthesis;
- compare interpretations;
- provide bounded context to AI collaboration.

Source registration does not imply mastery, correctness, authority, or publication of every statement in the source.

## Generated release artifacts

Generated release artifacts are derived outputs used by the browser and deployment process.

Examples include:

```text
public/data/learning-bundle.json
public/data/learning-bundle.manifest.json
public/styles.css
```

They are not canonical authored learning content.

They must be reproducible from repository-owned inputs and deterministic build rules, except for explicitly declared release metadata whose variability is intentional.

They must exclude private learner state.

## AI boundary

AI may use explicit learner input to propose:

- a clearer explanation;
- a contrast;
- a targeted question;
- a scenario;
- misconception remediation;
- the next bounded learning interaction.

AI must not independently assert that:

- the learner understands a concept;
- a learning artifact was effective;
- a misconception has been corrected;
- a competency has been achieved;
- a public object should be accepted because the learner answered once.

Such conclusions require explicit learner interaction, defined evaluation rules, or both.

## Mastery boundary

Repository acceptance and learner mastery are separate decisions.

```text
accepted repository object
    !=
learner mastery
```

Similarly:

```text
correct immediate answer
    !=
durable retention
```

and:

```text
self-reported confidence
    !=
demonstrated application
```

Future progress features must preserve these distinctions.

## Privacy boundary

Private learner state must remain separate from public repository releases.

The architecture may use:

- ignored local files;
- an external application-data location;
- another explicitly private storage mechanism.

It must not create an accidental second public content tree.

The implementation should avoid introducing persistent `.authoring/` or `.private/` repository infrastructure.

## Current implementation impact

This ADR is documentation-only.

It does not:

- introduce a new private-state implementation;
- change `study-state.schema.json`;
- change bundle generation;
- change current content objects;
- change frontend behavior;
- add mastery calculation;
- add review scheduling;
- add adaptive learning.

## Consequences

### Positive

- Repository status cannot be mistaken for learner understanding.
- Private learner observations remain outside public releases.
- Source material retains a useful but secondary role.
- AI cannot turn uncertain learner signals into authoritative mastery claims.
- Future learner-feedback work has a clear architectural boundary.

### Costs

- Some information must be stored and processed outside the public content model.
- Future progress views must combine public learning objects with private state without publishing that state.
- Acceptance of content and assessment of learning require separate workflows.

These costs are accepted because the distinction is fundamental to a learner-centered system.
