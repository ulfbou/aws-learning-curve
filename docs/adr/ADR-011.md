# ADR-011 Bounded chat-AI authoring transactions

Status: Accepted after correction.

## Decision

Python owns deterministic source preparation, validation, path derivation,
revisioning, hashing, dry-run reporting, generation-run recording, and
transactional application with best-effort rollback.

The chat AI owns semantic interpretation and drafting. It returns a portable
YAML transaction rather than repository paths or arbitrary repository files.

## Increment 1 goal

Prove this vertical slice:

```text
one deterministic UTF-8 text packet
    -> one bounded chat-AI transaction
    -> one validated candidate-only application
    -> existing repository validation
```

## Invariants

- Inputs are UTF-8 `.txt` and `.md` files.
- Packets and private inputs remain under ignored `.authoring/` and `.private/`.
- The packet source must already be a registered backend source object.
- Registered source ID, origin content hash, fragment IDs, and fingerprints
  must match the packet before application.
- Source metadata publication policy is explicit.
- Source metadata policy defaults to `forbidden`.
- Source metadata policy is not inferred from `source_type`.
- AI-created and AI-modified content always enters as `candidate`.
- Every AI-created claim references registered source fragments.
- The AI cannot choose repository paths.
- The AI cannot supply revisions, timestamps, content hashes, or run IDs.
- Python derives repository paths.
- Python computes revisions, timestamps, and hashes.
- Updates require an expected prior content hash.
- The complete staged candidate tree must pass the existing validator before
  repository files are replaced.
- Multi-file replacement uses best-effort rollback and is not described as
  atomic.
- The command never commits or publishes.

## CLI

The frontend repository provides:

```text
scripts/authoring.py ingest
scripts/authoring.py prepare
scripts/authoring.py apply
scripts/authoring.py apply --dry-run
```

A separate `review` command is deferred. `apply --dry-run` is the Increment 1
human-review surface.

## Registered sources

Increment 1 does not support packet-only provenance.

A packet's `source.id` must resolve to a source object under backend
`content/sources/**`. Before application, the command compares:

1. packet source ID
2. registered backend source ID
3. packet and registered `origin.content_hash`
4. packet and registered fragment IDs
5. packet and registered fragment fingerprints

A missing source fails before staging or writing:

```text
authoring failed: <source-id> is not registered in backend content
```

Private-source publication semantics, automatic source registration, and
alternative provenance models are deferred.

## Application semantics

Application performs these steps:

1. Parse the complete transaction.
2. Validate the transaction envelope.
3. Parse the complete source packet.
4. Verify the packet hash.
5. Require the packet source to exist in backend content.
6. Compare source identity, origin hash, fragment IDs, and fingerprints.
7. Verify every source and fragment reference.
8. Reject statuses other than `candidate`.
9. Reject AI-supplied system fields.
10. Derive repository paths.
11. Reject unsafe or invalid IDs.
12. Enforce optimistic concurrency for updates.
13. Add authoritative revisions, timestamps, hashes, and run IDs.
14. Validate proposed objects against existing schemas.
15. Generate a generation-run record.
16. Stage the complete candidate content tree.
17. Run the existing validator against the staged tree.
18. In dry-run mode, report the effect without writing.
19. Otherwise, replace files individually.
20. Attempt best-effort rollback if a replacement fails.
21. Never commit or publish.

## Deferred

- PDF extraction
- HTML extraction
- web capture
- OCR
- Pluralsight-specific parsing
- automatic source registration
- packet-only source provenance
- source-schema extensions
- semantic similarity search
- automatic duplicate merging
- automatic publication
- automatic fact verification
- personal study-state integration
